## ボトルネック（＝難所）

1. **トップ1枚では約半分しか拾えない（最大のボトルネック）**
   - 函館・福島（中核市でも）・舟橋村・竹富町で未発見。
   - 原因：採用が「くらし・手続き」等の**深い階層**にある／ナビが**JS・メガメニュー**で静的HTMLに出ない。
   - → トップだけでなく、**サイト内検索・サイトマップ・ナビ辿り**が必要。ここが虫食いゼロの致命点。

2. **アクセス遮断・レート制限のリスク**
   - 江差町が 503。連続アクセスで**ブロックされる懸念**（まさに設計が警戒する点）。1req/1秒以上・robots尊重が必須。

3. **URLの正確性（検証が必須）**
   - 志木市で別ドメインを返した。モデル/自動抽出の結果は**実在・200確認（検証）をしないと使えない**。

4. **「索引ページ」と「個別募集記事」の判別**
   - 新宿・加茂は採用トップではなく個別記事を取得。**どれを代表URLにするかの判定**が要る。

5. **ラベルの表記ゆれ**
   - 「職員採用／採用情報／職員募集／市職員募集／人事・職員採用」等。キーワード辞書を広めに持つ必要（これは対応容易）。

## 示唆

- **「見つかれば拾える」は約9割**（ページ上にリンクがあるケースでは発見精度は高い）。問題は**到達性（カバレッジ）**。
- v1.0の価値である**虫食いゼロ**に到達するには、トップ探索だけでは不十分。**「深掘り探索＋URL検証＋アクセス制御＋ロングテールの手動確認」**の4点セットが本番要件。
- コストの大半は「残り半分（深い階層・JSナビ・小規模自治体）」の攻略と、ブロックされない配慮に集中する。

## 本番クローラの設計案（GitHub Actions実行）

1. 各自治体：トップ→候補リンク抽出（キーワード辞書）。無ければ **(a)サイト内検索 (b)/sitemap.xml (c)よくあるパス（/saiyo/, /shisei/jinji/ 等）を試行**。
2. 候補URLを **HTTP 200＋本文に採用語を含むか** で検証。
3. **robots尊重・1req/1秒・UA明記**。503等はリトライ上限つきで退避、ブロック検知で停止。
4. 自動で拾えない分は `reports/saiyo-unmatched.csv` に出し、**月次で目視確定**（例規集と同じ運用）。
5. 全団体そろうまで**非公開**（虫食い回避）。
